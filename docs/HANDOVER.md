**当前状态**：签名与验签的**工具链已完备**，但生产密钥尚未生成与移交。

### 3.1 工具链已就绪（本条可执行）

仓库自带离线签名工具 `dounai-sign`（`src-tauri/src/bin/sign_manifests.rs`），
运维拿到私钥后即可完成全部操作，无需开发者介入：

```powershell
cd src-tauri

# 1) 生成密钥对（仅首次）
cargo run --bin sign_manifests -- keygen `
  --out-private D:\secure\priv.b64 --out-public D:\secure\pub.b64

# 2) 给每个 manifest 签名（就地写回 signature.value）
cargo run --bin sign_manifests -- sign `
  --key D:\secure\priv.b64 --manifest ..\manifests\omninexus.json

# 3) 发布前逐个验签
cargo run --bin sign_manifests -- verify `
  --pubkey D:\secure\pub.b64 --manifest ..\manifests\omninexus.json
```

已实测三条路径（真实 manifest）：
未签名 → 验签失败；签名后 → 验签通过；篡改 `entry.command` → 验签失败。

### 3.2 公钥如何进入发布构建

在 `src-tauri/src/main.rs` 的 `build_trust_policy()` 中，把
`TrustPolicy::strict(Vec::new())` 换为 `TrustPolicy::strict(vec![公钥base64])`。

**在配置公钥之前，发布构建是 fail-closed 的**：任何安装都会被拒绝。
这是刻意的取舍——宁可装不上，也不装来路不明的模块。

### 3.3 私钥保管要求

- 只存放于离线介质或受控密钥库，**不得**进入仓库、CI 变量、聊天工具；
- `.gitignore` 已排除 `*.b64` / `*.key` / `*.pem` / `priv*`；
- 私钥泄露时按 K4 轮换：生成新密钥对、重签全部 manifest、
  在新版本内置新公钥（旧公钥保留一段时间以便平滑过渡）。

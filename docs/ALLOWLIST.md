# 出网白名单

> 出网白名单必须随版本公开，并与供应链防线配合。
> 本文件随版本发布，用户可据此核对启动器的每一次联网行为。

---

## 1. 当前版本的白名单：**空集**

```text
（无）
```

**当前版本的启动器不允许任何出网连接。**

这不是配置遗漏，而是有意的保守取值：模块下载源与清单服务器尚未部署（见
[权限交接清单](HANDOVER.md)），在没有可信源的情况下开放联网只会扩大攻击面。

### 这意味着什么

| 功能 | 当前可用性 |
|---|---|
| 模块卡片浏览、套装规划 | ✅ 可用（数据打包在应用内） |
| 环境体检（Python/Node/GPU/磁盘） | ✅ 可用（纯本地探测） |
| 模块启用/停用/卸载 | ✅ 可用（纯本地操作） |
| 数据清除 | ✅ 可用 |
| 拉取模块清单 | ❌ 被白名单拒绝 |
| 下载模块包 | ❌ 被白名单拒绝 |

界面在环境页显示「安全模式（拒绝未签名）」，在安装时逐条列出真实阻塞项，
不会伪造"正在下载"。

## 2. 白名单如何生效（三层收口）

任何一次联网都要同时穿过三层，缺一层都不算真正拦住：

| 层 | 位置 | 作用 |
|---|---|---|
| 1. 前端 CSP | `src-tauri/tauri.conf.json` → `connect-src 'self'` | 禁止 WebView 直接发起任何外部请求 |
| 2. 域名白名单 | `src-tauri/src/catalog.rs::Allowlist` | 只放行 `https` + 白名单域名，**拦截后不发起请求** |
| 3. 逐源校验 | `commands.rs::download_package` | 多源下载时，**任一源不合规即整体拒绝** |

第 3 层为什么不"跳过坏源继续"：静默跳过会让配置错误永远不被发现，
运维以为在走镜像 A，实际一直在走 B。

### 白名单规则细节

- 只允许 `https://`：`http://` 会被中间人篡改，而清单决定装什么，一次篡改就构成供应链投毒；
- 支持精确域名与单层通配（`*.example.com`）；
- 裸域名不被 `*.` 匹配；`example.com.evil.com` 不会被 `example.com` 误匹配；
- **不跟随 HTTP 重定向**：重定向目标可能不在白名单内，跟随等于绕过白名单。

以上每一条都有对应测试（`catalog.rs`、`http_client.rs`）。

## 3. 明确不会做的事

启动器**不会**：

- 上传对话内容、记忆库、声纹、密钥、使用日志、安装日志；
- 携带任何遥测、崩溃上报或使用统计；
- 在用户未触发安装/更新的情况下发起网络请求；
- 使用 `http://` 明文协议获取任何内容；
- 把用户数据作为请求参数发给任何服务器。

## 4. 如何自行验证

### 方法一：看应用内

启动器 → 环境页 → 「模块签名策略」分组；若未来配置了白名单，
该列表会在拉取清单时一并返回并展示。

### 方法二：抓包

```powershell
# 启动启动器后，观察是否有非 127.0.0.1 的出网连接
Get-NetTCPConnection -State Established |
  Where-Object { $_.RemoteAddress -notin @('127.0.0.1', '::1', '0.0.0.0') } |
  Select-Object RemoteAddress, RemotePort, OwningProcess
```

预期：当前版本除系统自身的连接外，**启动器进程不产生任何外部连接**。

### 方法三：看代码与测试

```powershell
cd src-tauri
cargo test catalog:: -- --nocapture   # 白名单规则
cargo test download:: -- --nocapture  # 逐源校验与拒绝
```

其中 `fetch_blocked_by_allowlist_does_not_call_network` 断言：
白名单拦截后**调用列表为空**，即根本没有发出请求。

## 5. 未来接入下载源时的要求

配置真实下载源时必须同步完成：

1. 在 `src-tauri/src/main.rs` 的 `Allowlist::new([...])` 中列出域名；
2. 在 `tauri.conf.json` 的 CSP `connect-src` 中列出同一批域名；
3. 更新本文件第 1 节，把空集替换为实际列表；
4. 在 PR 中说明新增域名的用途与所有者。

三条必须一致——只改一处会造成"文档说允许、代码却拦着"或
"代码放行了、用户不知道"。

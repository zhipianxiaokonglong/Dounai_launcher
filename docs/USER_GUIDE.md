# Dounai 启动器 · 用户文档

> 启动器是产品的**第一入口**：负责「装、配、修、卸」，悬浮窗负责「跑」。
> 本文说明启动器的安装、环境与模块管理。

---

## ⚠️ 先读这一段：当前没有软件源

**本版本无法在线安装模块。** 模块下载源与签名公钥都还没部署，
出网白名单是空集，启动器不允许任何出网连接。

所以你打开程序后会发现「开始安装」点不动、「刷新模块清单」提示不可用——
**这不是坏了，是刻意的**：在没有可信源的情况下开放联网，等于给供应链投毒留门。

### 现在能做什么 / 不能做什么

| 能做 | 不能做 |
|---|---|
| 体检环境（Python / Node / uv / 显卡 / 磁盘） | 在线下载模块 |
| 用本地 zip 安装模块（会先算哈希） | 一键套装自动装齐 |
| 启动 / 停止 / 卸载**已安装**的模块 | 拉取模块清单与更新 |
| 一键启动整套、全部停止 | 推荐下载大体积模型 |
| 清除本地数据 | — |

### 想装模块怎么办

目前只有一条路：**拿到模块的 zip 包，用「从本地文件安装」**。

路径：套装页底部 → 「从本地文件安装」→ 选 zip、填模块 id、选分类 → 「校验并安装」。

装好后卡片上会出现「启动」按钮，可以正常启停。

> 如果你看到「未配置签名公钥」的提示，说明当前是发布版的安全模式：
> 未签名包会被拒绝。这是有意的门槛，不要尝试绕过。

如何接入真实软件源见 [README 的说明](../README.md#️-当前状态没有软件源重要)。

## 1. 它是什么

一个独立运行的桌面工具，管五件事：

| 能力 | 说明 | 当前可用性 |
|---|---|---|
| 启动 / 停止 | 拉起、停止模块，一键启停整套 | ✅ |
| 依赖安装 | 自动装各模块的运行时与库依赖；失败可续传、可回滚 | ⚠️ 引擎就绪，无源可用 |
| 环境管理 | 检测 Python / Node / GPU / 磁盘，给出体检结论 | ✅ |
| 模块管理 | 卡片式界面，看每个模块的依赖、权限、占用，可装可卸 | ✅ |
| 一键套装 | 预设组合，勾选后按依赖顺序自动装齐 | ⚠️ 计划可算，无源装不了 |

**与悬浮窗的关系**：启动器装好环境、修好配置，然后启动悬浮窗。
两者都可独立安装、独立运行。

---

## 2. 最小安装原则（最重要的一条）

> **安装器只装"跑起来必需的东西"；大体积模型权重一律不预装、只推荐。**

具体表现：

| 类别 | 内容 | 行为 |
|---|---|---|
| 必装 | 启动器本体、输入/模型/UI 核心、运行依赖、Reserved 插件 | 自动装，**不可勾除** |
| 推荐不预装 | 本地 LLM、本地 TTS、离线语音包 | 只显示推荐角标，**默认不装** |
| 可选自选 | BYOK 厂商配置、风格映射 | 你自己决定 |

**怎么验证这一点**：在套装页选「最小可用」，安装计划里
「模型包」一定是 **0 个**。轻量版和完整体验同样如此——
它们只在下方列出"推荐但默认不安装"的条目。

如果你看到某个预设套装默认勾选了模型权重，那是 bug，请报告。

---

## 3. 四种套装

| 套装 | 含什么 | 模型权重 |
|---|---|---|
| **最小可用**（默认） | 启动器 + 核心模块 + 运行依赖 | 无 |
| **轻量版** | 最小可用 + 语音层 | 无（推荐 1 个小模型，不勾选） |
| **完整体验** | 全部功能模块 | 推荐 3 个，默认都不勾 |
| **本地离线版** | 全部 + 本地模型 | 含 2 个，**需你显式确认** |

「本地离线版」装完就完全不依赖网络，代价是磁盘占用大。
因为它会装模型权重，所以必须先点确认才会开始。

## 4. 启动与停止

**装好不等于在跑。**「启用」只表示模块允许被拉起，「启动」才是真的把进程拉起来。

| 操作 | 含义 | 在哪 |
|---|---|---|
| 启动 | 拉起模块进程并做健康检查 | 模块卡片「启动」按钮 |
| 停止 | 终止进程并回收句柄 | 卡片「停止」按钮（运行中才出现） |
| 重试 | 先停再启 | 启动失败后卡片出现「重试」 |
| 一键启动 | 按依赖顺序拉起整套 | 环境页「维护」→「启动」 |
| 全部停止 | 逆序停止所有模块 | 环境页「维护」→「全部停止」 |

### 4.1 状态怎么看

卡片上有两个独立徽标，不要混淆：

- **已安装 / 已停用**：包在不在、允不允许跑；
- **运行中 / 启动中 / 已停止 / 启动失败**：进程在不在跑。

启动失败时悬停徽标可看到原因（健康检查未通过、进程提前退出等），
失败原因也会写进环境页的日志区。

### 4.2 启动顺序

一键启动按固定顺序：输入层(:8101) → 模型层(:8102) → 语音层(:8103) → 悬浮窗。

**任一模块失败不阻塞其余**——这是刻意的：少一个上游时，其余功能仍然可用，
只有依赖它的那部分会降级。停止时按相反顺序进行。

### 4.3 什么不能被启动

| 情况 | 行为 |
|---|---|
| 未安装 | 按钮禁用，显示「未安装」 |
| 已停用的可选模块 | 按钮禁用，提示「已停用，先启用」 |
| Reserved 类 | 默认禁用，永不参与启动 |
| 入口类型不是命令 | 拒绝启动并说明原因 |

## 5. 添加已经拉到本地的模块

用 `git clone` 或手工下载把模块放到本地后，启动器**不会自动发现**它——
卡片只来自内置清单。需要手动登记一次。

> ⚠️ **这是开发者功能，默认隐藏。**
> 普通用户装模块应走软件源（当前尚未部署）。把本地目录登记成可执行模块
> 属于开发流程，因此入口被刻意收敛，不在界面上直接暴露。

### 5.1 怎么开启

1. 打开「模块」页；
2. **连续点击左上角标题「Dounai 启动器」5 次**（2 秒内）；
3. 顶部出现「手动添加本地模块」区块。

**注意：该开关只在本次运行期间有效**，关掉启动器后需要重新开启。

### 5.2 怎么加

1. 填模块目录（包含 `manifest.json` 的那一层）；
2. 不确定在哪？填**上级目录**后点「扫描」，它会递归往下找
   （最多 6 层，自动跳过 `node_modules` / `target` / `.venv` 这类巨型目录）；
3. 点「添加」；候选较多时可「批量添加」，一次登记多个。

登记后卡片上会出现「本地目录」徽标，可以正常启动/停止。

### 5.3 三条要知道的规则

| 规则 | 说明 |
|---|---|
| **不复制文件** | 只登记路径。所以几十 GB 的目录也不会被复制一份 |
| **按钮叫「解除登记」** | 只让启动器不再管理它，目录里的文件原封不动 |
| **任何路径都不删文件** | 即使走「卸载」或「清除本地数据」，链接模块的目录也不会被删 |

第三条是硬约束：删掉用户自己 clone 的源码目录是不可接受的破坏性操作，
代码里有专门测试守着这条。

### 5.4 「本地拉取的模型」和「模块」不是一回事

这是最容易混的地方：

| 你手上的东西 | 能不能作为模块添加 |
|---|---|
| 含 `manifest.json` 的模块目录（源码仓库 / 模块包） | ✅ 可以 |
| 模型权重文件（`.gguf` / `.safetensors` / Ollama 模型等） | ❌ 不行 |

模型权重是**数据**，不是**模块**。它由对应的模块（如模型层 / 语音层）自己读取，
不需要登记成模块。若你把权重目录填进去，启动器会明确提示：

> 如果你拉取的是模型权重而不是模块，它不是可添加的模块。

### 5.5 安全边界

添加本地模块会**执行该目录里的代码**，当前约束如下：

- 目录里必须有合法 `manifest.json`，且 `module_id` 通过文件名校验；
- **本通道不校验签名**（与「从 zip 安装」不同）——理由见下；
- 启动时 `working_dir` 被限制在该模块根内，越不出去；
- 已被启动器正常安装的同名模块，不允许被本地目录顶替（需先卸载）；
- 卸载/解除登记/清除数据**都不会删除**该目录里的文件。

> **为什么这条通道不验签**：本地开发的模块不会有人去签名，强制验签会让
> 这个功能直接不可用。安全性由"开发者自己指定目录 + 入口默认隐藏"来兜底，
> 而不是由签名兜底。
>
> **代价要说清楚**：入口的 5 次点击（或开发者自建的目录）**不构成真正的安全边界**。
> 所以：只添加你自己 clone、或从可信来源下载的目录，不要添加来路不明的包。
>
> 「从 zip 安装」通道则仍然按信任策略验签，发布版拒绝未签名模块。

## 6. 厂商与密钥（第三方接入）

三个上游各自从**环境变量**读密钥，但配置方式互不相同：

| 层 | 读取方式 | 缺省配置手段 |
|---|---|---|
| 输入层 | 只认环境变量 | 明确不读 `.env`，也不从 TOML 读密钥 |
| 模型层 | 环境变量，`.env` 仅作填充 | 仓库根 `.env` |
| 语音层 | 只认环境变量 | `.env` 仅作填充 |

以前要分别改三套文件，还常配漏。现在启动器统一管：

### 6.1 怎么配

1. 打开「厂商」页，点「刷新厂商状态」；
2. 每层会列出所有厂商，标出**还缺哪个环境变量**（只显示变量名）；
3. 在对应输入框粘贴密钥 → 保存；
4. **重启该层模块**（环境页「全部停止」再「一键启动」）。上游只在启动时读环境变量。

### 6.2 三个要点

- **不回显**：保存后界面只显示「已保存」，任何时候都不会把密钥值读回来。
- **不写你的代码目录**：密钥只存在启动器数据目录的 `vendor-keys.json`，
  启动模块时以**进程环境变量**注入——不会往仓库里写 `.env`。
- **只有运行中的层能读到厂商清单**：状态按健康端点判定，
  所以启动器重启后也能认出「其实还在跑」的上游。

### 6.3 为什么不用写 `.env` 的办法

输入层明确「Secrets 永不从 TOML 读」，而且根本不加载 `.env`。
写文件对它就无效；而注入环境变量三层通吃，也不污染用户仓库。

## 7. 界面说明

### 7.1 模块页

每个模块一张卡片，显示：

- **分类徽标**：`core`（不可卸载）/ `optional` / `reserved`（默认禁用）
- **运行依赖**：共几项、缺几项
- **模型包**：几个，其中几个是推荐
- **网络权限**：显示"无（纯本地）"表示该模块不出网

点「详情」看完整信息（入口命令、健康检查地址、每个依赖与模型包的细节）。

> `reserved` 类的模块（记忆插件）会显示「不可卸载」，
> 这是设计要求，不是界面出错。

### 7.2 套装页

选一个套装 → 下方出现**安装计划**：

- 每一行是一个安装步骤，标 `🔒 不可勾除` 的是核心或 Reserved 模块
- `📦` 开头的是模型权重（只有离线版才会有）
- 最下方是「推荐但默认不安装」列表

### 7.3 环境页

点右上角「检测环境」运行体检：

| 分组 | 看什么 |
|---|---|
| 运行时 | Python / Node / uv 是否可用、版本是否够 |
| 显卡 | 显存多少，够不够跑本地模型 |
| 磁盘 | 剩余空间是否够装当前计划 |

> 在**非桌面端**（如浏览器里打开）时会显示「需桌面端」——
> 因为浏览器拿不到本机命令执行权限。这是如实反映，
> 不是伪造一个"检测通过"。

## 8. 安全说明

启动器会执行本机命令、解压文件，因此安全要求比普通工具高。

### 8.1 我们防了什么

| 威胁 | 措施 |
|---|---|
| 恶意压缩包写出目标目录 | 解压前逐条校验路径，含 `..`、绝对路径、UNC、Windows 保留设备名（`con`/`nul` 等）一律**整体拒绝** |
| 下载内容被篡改 | SHA-256 校验，不匹配即删除并换源 |
| 模块被植入后门 | manifest Ed25519 签名，篡改 `entry.command` 或 `permissions` 会验签失败 |
| 装到一半失败留下半残环境 | 先写临时目录，成功才原子替换；覆盖旧版先备份，失败自动还原 |
| 单个模块崩溃拖垮整个安装 | 安装事务隔离，失败只回滚该模块 |

### 8.2 出网白名单

启动器**只允许**访问模块目录与下载源，白名单随版本公开。
禁止上传对话、记忆库、声纹、密钥、使用日志、安装日志。

### 8.3 断网可用性

断网时：模块管理、已装模块的运行、历史查看全部可用；
只有"安装新模块/拉取更新"会明确提示不可用。

## 9. 常见问题

### 9.1 提示"缺运行时"

按环境页的提示安装对应运行时。Python 建议 3.11+，Node 建议 20+。

### 9.2 安装到一半失败

启动器会自动回滚，磁盘上不会留下半装状态。
重新点安装即可，已下载的部分会**断点续传**，不会从头再来。

### 9.3 提示"哈希校验失败"

下载内容与预期不一致（可能网络中断或源被污染）。
启动器会自动换下一个源。如果所有源都失败，说明镜像同步有问题，
稍后重试或换网络环境。

### 9.4 提示"验签失败"

manifest 签名与内容不匹配——可能是文件被改动，或签名密钥换了。
**不要绕过**，请联系维护者。绕过验签等于让后门合法化。

### 9.5 离线环境怎么装模块

套装页底部有「从本地文件安装」：选一个 zip、填模块 id、选分类，点安装即可。

- 会先算 SHA-256 再安装，哈希不符直接拒绝，不会解压；
- 压缩包内若有 `../` 或绝对路径条目，整包拒绝，不会写出目标目录；
- **发布版还会校验签名**，未签名包会被拒（调试版放行）——
  所以离线安装能否成功取决于你的版本与策略，环境页可查当前策略。

### 9.6 环境页显示"安全模式（拒绝未签名）"是什么意思

这说明当前版本**还没有内置签名公钥**，因此任何未签名的模块都会被拒绝安装。

这是有意的保守设置：启动器会按 manifest 决定"启动什么命令、开哪些权限"，
一个被篡改的 manifest 可以把恶意命令伪装成正常模块。所以在无法验签时，
宁可装不上，也不装来路不明的模块。

三种状态对照：

| 环境页显示 | 含义 | 能否安装模块 |
|---|---|---|
| 安全模式（拒绝未签名） | 无公钥，且不允许未签名 | ❌ 全部拒绝（fail-closed） |
| 开发模式（允许未签名） | 无公钥，但显式放开 | ✅ 仅建议开发时使用 |
| 已配置 N 个公钥 | 有可信公钥 | ✅ 仅接受验签通过的 |

如果正式版长期停在这里，说明签名密钥尚未完成交接（见 `docs/HANDOVER.md` 的「发布签名密钥」一节），
请联系维护者，而不是尝试关闭校验。

### 9.7 想彻底离线

选「本地离线版」套装，它会装本地模型权重。
装完拔网线也能正常对话、听语音。

### 9.8 磁盘不够

环境页会提前算好需要多少空间。可以先只装「最小可用」，
之后按需从模块页单独加装。

## 10. 技术栈

| 项 | 选择 | 理由 |
